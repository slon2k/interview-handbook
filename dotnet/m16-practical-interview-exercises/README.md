# Module 16 - Practical Interview Exercises

**Status:** Complete  
**Priority:** Critical  
**Prerequisites:** All prior modules (this module converts their content into interview performance).

## Scope

This module converts knowledge from every earlier module into interview performance. Unlike the reference-style topic files in Modules 2-15, each file here is a set of concrete practice exercises for one recurring interview exercise category — a problem statement, what a strong answer demonstrates, and the common mistakes that give away a weaker one. Every exercise deliberately draws on and cross-references specific topics from earlier modules rather than introducing new material.

## Learning Outcomes

By the end of this module, you should be able to:

- Solve short coding and LINQ tasks fluently and explain your reasoning as you go.
- Refactor flawed code by naming the specific smell and technique being applied.
- Diagnose broken code by forming and verifying a specific hypothesis before fixing it.
- Review a pull request for correctness, security, and design — not just style.
- Predict code output precisely for tricky value/reference, async, and LINQ scenarios.
- Design tests, endpoints, small services, and SQL queries that hold up to interviewer follow-up questions.
- Spot EF Core and async/concurrency problems by reading code alone.
- Hold an open-ended architecture discussion, adapting your recommendation as constraints change.
- Calibrate "what would you improve" answers — prioritizing real issues and recognizing when nothing needs to change.

## How This Module Differs From the Rest

Every other module follows the same topic template (Definition, Alternatives & Trade-offs, How It Works, Application, Common Mistakes, Common Interview Questions, Practical Tasks, Readiness Criteria, References). This module doesn't, deliberately — it's not teaching new concepts, it's rehearsing the application of concepts already taught. Each file instead follows: What This Assesses, Format and Time Expectations, several worked Exercises (each with a problem, what a strong answer demonstrates, and common mistakes), and Readiness Criteria.

## Suggested Learning Sequence

Work through these roughly in the order listed, but return to specific categories after reviewing their referenced modules if a gap shows up — this module works best as a repeated diagnostic, not a one-time read-through. A realistic prep schedule: do a category, note which referenced module content felt shaky, review that module's specific topic file, then retry the category.

## Practical Deliverables

- Time yourself solving one exercise from each category under realistic interview time pressure.
- For each debugging/code-prediction exercise, write down your hypothesis *before* checking the explanation, to calibrate how often your first instinct is correct.
- Practice narrating your reasoning out loud (not just solving silently) for at least the refactoring, code-review, and architecture-discussion categories, since verbal reasoning is itself part of what's being evaluated in a real interview.

## Interview Coverage

This module *is* interview coverage — every exercise category maps directly to a real, common interview exercise format. Treat "Common Mistakes" in each file as a checklist of what to deliberately avoid, and "What a strong answer demonstrates" as the bar to hit, not just the correct final answer.

## References

Each exercise category file links directly to the specific earlier-module topics it draws on — treat those links as your remediation path when an exercise reveals a gap.
